For multi-worker implementation, reuse the supplied ledger or create `.maki/orchestrate/<run>/` before dispatch. Small inline work and independent read-only questions do not need a ledger.

- The manager owns `plan.md`: task IDs, acceptance criteria, explicit dependencies, file/worktree ownership, status, and one verification owner per worktree. Split independent edits from dependent integration. Dispatch ready tasks together, without waiting for unrelated work to finish.
- The manager owns `notes.md`: compact shared discoveries and interface decisions. Each task has `tasks/<id>.md` containing its precise brief, known findings, symbol/hunk references, dependencies and handoff. Give its path through task's `ledger` input. Workers update only their own task record, never shared files concurrently. Read-only workers return a handoff for the manager to record.
- Read existing findings before rediscovering branch scope. Keep useful context through implementation. A replacement worker starts from the task record and shared notes, not a repeated full-code investigation. Return changed invariants, paths/ranges, blockers and command-result paths, not full source or diffs.
- Use background tasks when the manager has independent work, and blocking batches when it needs all results. Completion notices replace status polling. Finish dependent integration before aggregate verification.
- Workers do not build, test or format shared outputs while siblings edit the same worktree. The verification owner runs focused checks once edits settle, then aggregate checks after outstanding review fixes land. Isolated worktrees may verify independently. A compile failure from unfinished sibling work is not a reproduced regression.
- Execute a build/test once with useful failure logging and preserved exit status. Read retained output or result artifacts for diagnostics instead of rerunning unchanged commands to recover a summary. Recheck after a relevant edit or a justified transient failure. Inspect existing commands and startup requirements before expensive migration/tooling attempts.
- Final review checks changed invariants and acceptance criteria. The manager records evidence and unresolved risks before marking work done. Do not treat a worker's completion claim as verification.
